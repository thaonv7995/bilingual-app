# Backend Feature Guide

This document details the core capabilities and architecture of the FastAPI backend service.

## 1. Authentication & API Key Systems

The backend provides dual authentication mechanisms: JWT-based sessions for interactive clients (Web and iOS) and API keys for external automated tooling.

### JWT Session Flow
- **Registration (`/api/auth/register`)**: Creates a user with a hashed password using `bcrypt`.
- **Login (`/api/auth/login`)**:
  - Validates credentials.
  - Generates a short-lived JWT Access Token (15 minutes expiry) passed as an HttpOnly cookie or bearer token.
  - Generates a long-lived Refresh Token (30 days expiry) stored in the database.
- **Silent Refresh (`/api/auth/refresh`)**: Rotates access and refresh tokens seamlessly using the HttpOnly refresh token cookie, avoiding session drop-outs.
- **Logout (`/api/auth/logout`)**: Deletes the database refresh token record and clears client-side authorization cookies.

### API Keys
- Generated by admins through `/api/admin/apikeys`.
- Used in headers as `X-API-Key` to authorize script connections. It maps to a virtual admin session, enabling book compiler tools to push compiled book bundles directly.

## 2. Book Ingestion & Packaging (.bkb format)

Books are compiled and packaged into `.bkb` files. A `.bkb` file is a ZIP archive containing:
- `book.json`: Metadata such as title, author, total page count, and layout paths.
- `output/`: Processed primary and translated HTML pages (`output/en/page_0001.html`, `output/vi/page_0001.html`), images, styles, and covers.

### Operations
- **Upload (`/api/books/upload`)**: Unpacks the ZIP archive into `books/<slug>/` and registers the book's metadata into the database.
- **Download (`/api/books/<slug>/download`)**: Dynamically packages the book's folder workspace back into a `.bkb` zip stream for distribution.
- **Delete (`/api/books/<slug>`)**: Deletes the database metadata and thoroughly removes the file system directory workspace.

## 3. Secure File Server (Access Control)

To prevent unauthorized access to copyrighted or premium book assets, the backend intercepts direct static requests to book outputs:
- Route: `/books/{slug}/output/{path:path}`
- Logic:
  1. Resolves user details from the request (headers, cookies, or query parameters).
  2. If the user is an admin, access is immediately granted.
  3. If the user is a regular member, it checks the `user_permissions` table to verify if the user has read permissions for the specific `book_slug`.
  4. If validated, the file is securely streamed using `FileResponse`. Otherwise, a `403 Forbidden` or `401 Unauthorized` is returned.

---

## 4. Reading Progress & Annotations

- **Reading Progress (`/api/books/{slug}/progress`)**:
  - Automatically captures and saves the user's active page number and layout viewing mode (e.g. English, Vietnamese, or Split screen).
  - Syncs last read timestamps to allow simple list sorting on the library homepage.
- **Highlights (`/api/books/{slug}/highlights`)**:
  - Synchronizes user annotations, text highlights, selected colors, and paragraph notes.
  - Allows querying, adding, editing, and deleting highlights.

---

## 5. AI Assistant Streaming Proxy

- Route: `/api/chat`
- Purpose: Bypasses CORS issues and conceals sensitive OpenAI/Gemini/Ollama backend servers from public clients.
- Mechanics: Receives standard OpenAI-compatible JSON requests, adds authorization headers if necessary, and proxies the stream payload chunk-by-chunk using FastAPI's `StreamingResponse`.
